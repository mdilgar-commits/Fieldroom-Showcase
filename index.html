    02 / PRODUCT OVERVIEW

    Requirements are scattered.
    Rooms are not.

    Fieldroom turns a project’s drawings and specifications into a room-by-room matrix of deliverables, then tracks that work through closeout.

    The problem. On every construction project, the requirements for each room are spread across floor plans, specification sections, and scope documents. Teams rebuild that picture by hand in spreadsheets and binders, and items are easy to miss until closeout.

    The product. Fieldroom reads the documents with AI, proposes the rooms, trades, and deliverables it finds with their source sections, and lets a project manager confirm each one. The approved list becomes a shared checklist that field crews update from their phones.

    Who it is for.

    Project managers & project engineers

    Organize construction documents, review extracted requirements, manage deliverables, and identify incomplete work before closeout.

    Superintendents

    Monitor field progress, coordinate subcontractor activities, and verify that work is complete.

    Quality control & closeout teams

    Review room completion records, find outstanding items, and confirm required deliverables are done before turnover.

    Subcontractors & trade foremen

    Scan room QR codes to see assigned deliverables, review requirements, and update completion status.

    AI reads the documents.
    People make the call.

    When a project manager clicks Extract, Fieldroom sends the uploaded floor plan and specifications to Google’s Gemini 3.5 Flash Lite model. Gemini reads the drawings as images and the specifications as text, and returns structured results: the rooms, the responsible trades, each room’s deliverables, project-wide requirements, and the specification section behind every item.

    Fieldroom then splits combined requirements into one item per trade, removes duplicates, and places every suggestion in a review queue. Nothing reaches the room matrix until a person approves it.

    • Traceable. Every suggestion cites its source document, page, and section, and Fieldroom checks that the cited document, page, and section exist. Doubtful citations are flagged for the reviewer.
    • Completeness check. A second AI pass looks only for requirements the first pass missed, and marks anything it adds.
    • Human in the loop. Subcontractors, rooms, and requirements are each confirmed or edited.
    • Accountable. Every approval, completion, note, and photo is recorded with who made it and when.
    • Secure. The API key stays on the server and never reaches the browser or the code repository.
    • AI-assisted development. Claude Code was used to build, test, and fix the application.

    AI suggestions can be incomplete or wrong, so every item is reviewed against its cited source before it is used.

    06 / PRODUCT DEVELOPMENT & IMPROVEMENTS

    From midterm prototype
    to a working product.

    At the Midterm Showcase, Fieldroom was a prototype that ran on one computer. Since then the team focused on making it reliable, shareable, and easier to use.

    1

    Application startup issues

    Before: a startup bug stopped the application from running properly in Google AI Studio.

    Now: the bug is fixed, and Fieldroom is published as a public demo that anyone can open from a link.

    2

    Unreliable room map generation

    Before: the drawing-based room map glitched repeatedly and could stall the room review.

    Now: a searchable room list replaces the map, and the review moves straight from each room to its requirements. The map was turned off, not deleted, so it can return once it is reliable.

    3

    API integration problems

    Before: the Gemini API key was not reaching the application, so it could not communicate with the AI model.

    Now: the key is stored in Google AI Studio’s Secrets panel and sent the way Google’s new keys require. It never appears in the code or the browser.

    4

    Limited AI usage

    Before: the original model allowed only about 20 free requests a day.

    Now: Fieldroom uses Gemini 3.5 Flash Lite, which allows about 500 free requests a day, and explains key, quota, and model problems in plain language.

    5

    Code management issues

    Before: syncing code back from AI Studio overwrote newer fixes, and troubleshooting was hard to trace.

    Now: every fix follows one path, change → review → merge → publish, on its own GitHub branch and pull request, with automated tests and evidence-based troubleshooting.

    6

    Accountability tracking

    Before: there was no record of who completed, changed, or approved a deliverable.

    Now: the server keeps an activity log of every upload, AI extraction, approval, completion, note, and photo, with who and when. It appears in each deliverable’s history and on the Project progress page, and can be exported to CSV.

    7

    Improved AI accuracy

    Before: extraction was a single AI pass, and citations were not checked.

    Now: answers are more consistent, a completeness check finds requirements the first pass missed, and every citation is checked against the uploaded documents, with doubtful items flagged for the reviewer.

    07 / WHAT’S NEXT

    From demo
    to the jobsite.

    What a licensed team workspace adds, and the recommendations that guide what comes next.

    Fieldroom for your team

    The public demo is open to everyone and resets from time to time. Teams that license Fieldroom get a private workspace with three features designed to work together: sign-in protects the project, cloud storage keeps it, and separate projects keep each job organized.

    • Secure sign-in and roles. Each person signs in with their own account. Project managers manage setup and review; subcontractors see and update their assigned work.
    • Permanent cloud storage. Projects, documents, photos, and activity history are stored securely with Google Firebase, so nothing is lost when the app restarts.
    • Multiple projects. Every job gets its own documents, team, room matrix, and progress records, all under one account.

    Already included today: accountability tracking and improved AI accuracy (see improvements 6 and 7).

    Recommendations

    • Prioritize reliability. Make existing functions work consistently before adding features.
    • Broaden document compatibility. Test with different drawing formats, specification layouts, and project types.
    • Simplify navigation. Make switching between project information, room matrices, and deliverables easier for field personnel.
    • Improve data security. Add secure document storage and restricted project access before using confidential construction documents.
    • Focus on practical applications. Prioritize features that simplify field communication, progress tracking, and closeout.
